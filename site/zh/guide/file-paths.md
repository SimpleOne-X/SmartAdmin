# 文件路径

附件落在哪台文件服务器的哪个文件夹、怎么命名、谁能上传谁能下载，管理员在后台配一次就够了。业务代码只认一个编码：上传时拿回相对路径存进自己的表，下载时把编码和路径交回来。

内核原有的「文件管理」（`FileUpload` 组件、`/api/v1/sys/file/*` 接口）是另一套独立的上传下载。菜单里「文件管理」目录下并排放着两个页面，原有的「文件管理」页管那一套，「文件路径」页管这一套。两套的接口和组件不通用，同一个业务字段选定一套，别混着用。

## 先由运维放行根目录

文件服务器的根路径必须落在 `SmartAdmin:FilePath:AllowedRoots` 列出的目录里。白名单为空，所有根路径都会被拒绝（`44152`），配置页顶部也会提示先去配置。

白名单放在配置文件而不是界面里，因为它是安全边界。界面上的管理员如果能随便填根路径，就能把文件写进程序目录、静态站点目录，或者用 `\\127.0.0.1\c$\…` 这类共享路径绕回本机。新增一个共享要改配置并重启，由能登录服务器的运维来做。

```json
{
  "SmartAdmin": {
    "FilePath": {
      "AllowedRoots": [ "\\\\nas01\\files" ]
    }
  }
}
```

匹配按「白名单目录 + 分隔符」的前缀判断，白名单是 `\\nas01\files` 时，`\\nas01\files2` 不会被放行。保存时校验一次，每次使用前再校验一次（上传和下载报 `44152`），所以白名单改小之后，落在名单外的文件服务器立刻不可用。

整个配置节 `SmartAdmin:FilePath` 有四项：

| 配置项 | 默认 | 作用 |
|---|---|---|
| `AllowedRoots` | 空数组 | 根目录白名单，必须是绝对路径。空表示功能不可用 |
| `StagingPath` | `./data/file-path-staging` | 分片上传的暂存目录，相对路径按 ContentRoot 解析 |
| `StagingTtlHours` | `24` | 分片会话这么久没有新分片就当作放弃，暂存清掉。必须大于 0 |
| `LinkTtlMinutes` | `60` | 签名直链的默认有效分钟数，签发时可以另传。必须大于 0 |

不需要这个功能的部署，在 `SmartAdmin:Api:DisabledModules` 里加 `"FilePath"`，四个控制器的路由一起消失。服务注册还在，业务代码照常能注入。

## 登记文件服务器

入口在「文件管理」目录下的「文件路径」页，切到「文件服务器」页签。一台 NAS 的一个共享登记一行。这一页挂在系统菜单下，只有超管和被授权的内置角色看得到。新增、编辑、删除要求近期重新验证过身份（`[RequireReauth]`，用法见[认证与安全](/zh/backend/auth-security)）。测试连接不落库，不要求。

| 字段 | 说明 |
|---|---|
| 名称 | 唯一，最多 64 个字符 |
| 根路径 | 绝对路径，必须落在白名单内。Windows 写 `\\nas01\files\子目录`，也可以写成 `//nas01/files/子目录`；Linux 和 Docker 写容器里看到的挂载路径，如 `/mnt/nas01/files` |
| 账号 | `域\账号` 或 `账号`。留空表示用后端自己的运行身份访问。Linux 上这一项置灰 |
| 密码 | 加密后存库，接口从不返回，界面只显示「已设置」 |
| 启用 | 停用后，挂在它下面的文件路径全部不能上传和下载 |

几条保存时的规则：

- 填了账号时，根路径必须是 `\\主机\共享` 形式的共享路径（`44153`）。这条只在 Windows 上强制，Linux 本来就忽略账号。
- **同一台主机只用一套账号和密码。** Windows 对同一台主机只接受一套凭据，所以根路径主机名相同的行，账号和密码始终一致。新增一行，或者把根路径改到另一台主机时，账号要和那台主机已有的行一致，否则被拒绝（`44154`）。比较账号时不区分大小写，留空也算一种；主机名不区分大小写，也不做解析，`\\nas01` 和 `\\10.0.0.5` 算两台；已停用的行也参与比较。
- 密码留空表示不改。修改时换了主机或账号，密码必须重新填写，留空会被拒绝（`44157`）：旧密码不会带去新主机，也不会配给新账号。清空账号会把密码一起清空。
- 保存密码需要持久的数据保护密钥，否则被拒绝（`44156`），见下面的[部署](#部署)。
- 被文件路径引用的文件服务器不能删除（`44155`）。

在同一台主机上修改某一行的账号或密码，这台主机的其他行会在同一个事务里一起改成这个账号和密码，账号只差大小写也会统一成新的写法。清空账号时，这台主机上的所有行都改用后端的运行身份访问。编辑弹窗会在密码框下提示这一点。只改名称、备注等别的字段，不影响其他行。

编辑弹窗里的「测试连接」测的是当前填的内容，不用先保存，规则和保存一致，只是不查同一主机的账号是否一致，好让你在保存前先试新账号。用新账号测试会断开后端连着这台主机的旧连接，之后访问其他行时再按它们保存的账号重连。它依次试：连接（填了账号时）、根路径存在、可读（取到第一个条目就停，不列整个目录）。5 秒内没有结果报「超时」。编辑已有的行时密码留空，沿用库里已保存的密码，前提是主机和账号都没变。

列表上的「在线状态」并行检查各行的根路径是否存在，单行 3 秒超时，不写文件。多副本部署时，它反映的是处理这次请求的那个副本能不能访问。

改了账号或密码，不用重启，下次访问就换用新凭据。后端会先断开自己用旧凭据连着这台主机的所有共享，再用新凭据连接。多副本部署时，每个副本在下次访问时各自完成这一步。

## 配置文件路径

「文件路径」页签里，一行对应一类业务文件。

| 字段 | 说明 |
|---|---|
| 编码 | 业务代码引用它的键。只能用字母、数字、`.`、`_`、`-`，最多 64 个字符，保存后不能改 |
| 名称 | 最多 64 个字符 |
| 文件服务器 | 从已登记的服务器里选 |
| 子文件夹 | 相对服务器根路径，用 `/` 分隔，如 `Order/Attachment`。留空就是根路径本身。文件夹不存在时，首次上传会自动创建。下列写法保存时报 `44112`：绝对路径、含 `:`、空段（如 `a//b`）、以点开头的段（含 `..`）、以点或空格结尾的段。点开头的段下载时一律当作不存在，存进去的文件取不出来，所以直接拒绝 |
| 命名规则 | 见下表 |
| 同名处理 | 拒绝或覆盖，只对「业务指定路径」有意义 |
| 只读 | 只提供下载，不开放上传，也不设后缀和大小上限 |
| 后缀 | 允许上传的后缀，小写带点，逗号分隔，如 `.pdf,.png`。可写的行必填 |
| 大小上限 | 单个文件的上限，单位 MB。可写的行必填且大于 0 |
| 上传角色、下载角色 | 留空表示所有登录用户 |
| 启用 | 停用后上传、下载、签名直链都被拒绝 |

后缀和大小上限不继承「文件管理」的上传策略，两套上传互不影响。编辑弹窗会实时显示完整文件夹和一个示例文件名。

三种命名规则：

| 命名规则 | 相对路径 | 适合 |
|---|---|---|
| 年/月/原名_短ID | `{yyyy}/{MM}/{清洗后的原名}_{8 位十六进制}{后缀}`，如 `2030/01/报价单_3f9c2e1a.pdf` | 附件类。人看得懂，也不会重名 |
| 业务指定路径 | `{清洗后的 subPath}/{清洗后的文件名}`，`subPath` 可空，其中每一段也按文件名规则清洗（如 `:` 变成 `_`） | 打印模板、安装包这类路径本身有业务含义的文件 |
| 日期/GUID | `{yyyyMMdd}/{GUID}{后缀}`，如 `20300101/0198a3c4e5b27c61a8f90d1e2b3c4d5e.pdf` | 不在乎可读性，只求安全 |

年月和日期取服务器本地时间，文件夹是给人在资源管理器里翻的，按本地日期分才符合直觉。

上传时的校验和落盘规则：

- **文件名清洗**：`\ / : * ? " < > |` 和控制字符换成 `_`，开头的点换成 `_`，去掉末尾的点和空格，`CON`、`NUL`、`COM1` 这类 Windows 保留名前面加 `_`。不含后缀的部分最多保留 60 个字符，整个文件名在 UTF-8 下装得进 NAS 常见的 255 字节上限。业务指定路径的 `subPath` 逐段按同样的规则清洗，只有绝对路径、空段、`.` 和 `..` 这类清洗前去掉末尾点和空格后为空的段，以及清洗后超过 255 字节的段，才被拒绝（`44112`）。
- **后缀**取清洗后文件名的后缀，转小写后必须在白名单里。`报价.PDF` 能通过，落盘是 `.pdf`；`README` 这种没有后缀的文件一律拒绝。
- **大小**超过上限拒绝。分片上传在初始化时按声明的大小先拦一次，合并后按实际大小再拦一次。
- **同名**只出现在「业务指定路径」。处理为拒绝时报 `44111`；处理为覆盖时先写同文件夹里的临时文件，写完再替换。写到一半失败，旧文件原样保留；正在被下载的文件也能被覆盖。

`subPath` 来自前端，能上传这一行的人就能覆盖这个文件夹里任何同名文件。所以覆盖类的行应当配上传角色，配置页在「同名覆盖且上传角色为空」时会给出警告。

::: warning 改文件服务器或子文件夹不会搬走老文件
业务表里的相对路径会指向新文件夹，老文件在新位置读不到。改之前先把旧文件搬过去，业务数据就不用动。配置页编辑时有同样的提示。
:::

「测试连接」同样测弹窗里当前填的内容。可写的行会在文件夹里写入、读回、删除一个 `.smartadmin-probe-{GUID}` 文件，文件夹不存在时先创建；只读的行只检查文件夹存在。

## 谁能上传、谁能下载

上传和下载接口不挂菜单按钮，只要求登录，再按这一行配的角色判断：

- 超管放行。
- 角色留空：所有登录用户都可以。
- 否则：当前用户**已启用**的角色和列表有交集才放行，停用的角色不算数。

业务用户因此不需要被授予任何系统菜单。内核规定系统菜单只能授给内置角色，上传下载要是挂在系统菜单的按钮上，业务角色就拿不到权限。

用户级的单独授权（给某个用户额外允许或拒绝一个菜单）影响不到这里，这里只认角色。文件服务器的账号属于后端，和登录用户无关。

编码不存在或已停用时，角色判断之前就先报 `44101`。

## 业务怎么接

### 上传：`FilePathUpload` 组件

组件从 `smart-admin-web` 导入，封装了 `n-upload`，上传成功时发出 `uploaded`：

```vue
<FilePathUpload
  code="Order.Attachment"
  :show-file-list="false"
  @uploaded="out => (form.attachmentPath = out.path)"
>
  <n-button>上传附件</n-button>
</FilePathUpload>
```

| 属性或事件 | 说明 |
|---|---|
| `code` | 必填，配置页里登记的编码 |
| `subPath` | 仅命名规则是「业务指定路径」时有用，文件落在文件夹下的这个子路径里，其余规则服务端忽略 |
| `uploaded` | 单个文件上传成功后触发，多选时每个文件各一次。载荷是 `{ path, name, size, viewUrl }` |
| `loadingChange` | 单个文件上传的开始和结束各触发一次，给触发器加「上传中」状态用 |

`accept`、`multiple`、`show-file-list` 等其余属性原样透传给 `n-upload`，默认插槽就是触发器。失败时组件自己弹出错误提示，并把该项标红。

超过 20 MB 的文件自动分片：在浏览器里算整文件 SHA-256，向服务端初始化拿分片大小和片数，并发传片，最后合并。进度回给 `n-upload` 的进度条，传片阶段最多到 99%，服务端合并完成后才到 100%。同一次上传里，分片或合并遇到网络错误、超时、服务端 5xx 或文件夹暂时无法访问（`44114`），分别在 1、2、4 秒后重试，三次重试都失败才算失败。文件服务器出现网络类失败后要挡 30 秒（见[文件夹无法访问](#文件夹无法访问)），这几次重试等不到它放行。合并报缺片（`44115`）时，补传缺的那一片再合并一次。任何一片最终失败，其余在途的分片随即取消；组件卸载时，在途的上传也一起取消。关掉页面或重新选择文件就要整个重传，也没有秒传。SHA-256 是把整个文件读进浏览器内存算的，所以实际能传多大的文件受浏览器可用内存限制。

### 直接调接口

不用这个组件的客户端，调下面四个接口。它们都只要求登录，角色由文件路径的配置决定：

| 方法 | 路由 | 说明 |
|---|---|---|
| POST | `/api/v1/sys/file-path/upload/{code}` | 单文件上传，multipart：`file`，可选 `subPath` |
| POST | `/api/v1/sys/file-path/upload/{code}/chunk/init` | 分片初始化：`fileName`、`size`、`sha256`（64 位十六进制）、可选 `subPath`。只读、后缀、大小、角色都通过才返回 `uploadId`、`chunkSize`、`chunkCount` |
| POST | `/api/v1/sys/file-path/upload/{code}/chunk` | 上传一个分片，multipart：`uploadId`、`index`（从 0 起）、`chunk` |
| POST | `/api/v1/sys/file-path/upload/{code}/chunk/complete` | 请求体 `uploadId`。合并、核对 SHA-256 和大小，按命名规则写入 |

两种上传的返回值都是 `{ path, name, size, viewUrl }`。`path` 是相对路径，`name` 是清洗后的原文件名，`viewUrl` 是签名直链（见下面的[签名直链](#签名直链)）。

分片大小由服务端定，客户端按 `chunkSize` 切，最后一片可以短。`uploadId` 由服务端生成，绑定当前用户和编码，别人拿到也用不了。分片先暂存在 `StagingPath/{uploadId}/`。合并成功，或者核对没通过（哈希不符、规则已经不允许、业务路径撞名）后删掉；文件夹暂时无法访问这类存储失败时保留，原样再合并一次即可。超过 `StagingTtlHours` 没有新分片的会话由后台清扫。

单文件接口的请求体沿用框架默认上限，Kestrel 和 IIS 都是 30,000,000 字节（约 28.6 MB），内核不调大。组件对超过 20 MB 的文件走分片，所以大小上限配得再大也不受影响；自己写客户端的话，大文件同样要走分片。

### 业务表存什么

存 `path`，需要显示原文件名时再存 `name`。不存完整的 UNC 路径，也不存 `viewUrl`：

- 相对路径不含服务器根路径，改了文件服务器的根路径之后，只要把旧文件搬过去，业务数据不用改。
- `path` 里的文件名可能被命名规则改过，原文件名要显示就得单独存 `name`。
- `viewUrl` 会过期，需要时由后端现签。

### 下载

前端用 `filePathFileApi.download` 取字节，再用 `triggerBlobDownload` 落盘：

```ts
import { filePathFileApi, triggerBlobDownload } from 'smart-admin-web'

const blob = await filePathFileApi.download('Order.Attachment', row.attachmentPath, row.attachmentName)
triggerBlobDownload(blob, row.attachmentName)
```

底层是 `GET /api/v1/sys/file-path/download/{code}?path=&name=`，要求登录并满足这一行的下载角色。文件一律作为附件返回，带 `nosniff`，支持 Range 断点续传。

- `name` 可选，只决定浏览器保存时的文件名。它清洗后，后缀强制换成磁盘文件的真实后缀，调用方没法借它把 `.pdf` 改成 `.exe`。不传就用磁盘上的文件名。
- 下载不看后缀白名单，因为只读的行里本来就有各种后缀的老文件。
- 相对路径里任何一段以 `.` 开头，一律当作文件不存在（`44113`）。测试连接的探针文件、覆盖时的临时文件、系统隐藏文件都是这种。

### 后端直接调服务

删除没有 HTTP 接口，只有后端服务方法，由业务在删单据、换附件时调用。几个服务都在 `SmartAdmin.Services` 命名空间，签名器在 `SmartAdmin.Core`：

| 服务 | 方法 | 用途 |
|---|---|---|
| `IFilePathUploadService` | `UploadAsync`、`DeleteAsync` | 后端自己产生的文件（导出的报表之类）写进文件夹，或删掉文件夹里的一个文件 |
| `IFilePathDownloadService` | `OpenReadAsync(code, path)` | 返回已打开的只读流，调用方负责释放 |
| `IFilePathDownloadService` | `GetFullPathAsync(code, path)` | 返回完整路径，给要自己打开文件的程序。只做路径运算，不检查文件在不在 |
| `IFilePathLinkSigner` | `BuildUrl(code, path, ttl?)` | 签出直链 |

```csharp
public class OrderAttachmentService(IFilePathLinkSigner signer, IFilePathUploadService uploads)
{
    // 业务表里只有 path，预览链接按需现签
    public string PreviewUrl(string path) => signer.BuildUrl("Order.Attachment", path);

    // 删单据或换附件时，由业务自己删文件
    public Task RemoveFileAsync(string path, CancellationToken cancellationToken) =>
        uploads.DeleteAsync("Order.Attachment", path, cancellationToken);
}
```

后端代码直接调这些服务时**不做角色判断**，由调用它的业务自己负责。只读、后缀、大小、路径这些规则校验照常生效。

这些内置服务都用 `TryAdd` 注册，要换实现照[替换内置服务](/zh/guide/replace-service)的写法。

## 签名直链

`<img src>` 带不了 `Authorization` 头，客户端也可能根本没有令牌。签名直链就是为这种场景准备的：它匿名可读，但不可伪造，拿得到链接才拿得到文件。

链接有两个来源：一是上传接口返回的 `viewUrl`，二是后端代码调用 `IFilePathLinkSigner.BuildUrl` 按需签发。后一种比如业务列表接口给每行图片带一个预览链接，或者给不登录的客户端发安装包的下载链接。签出的是以 `/api/v1/sys/file-path/download/{code}/view` 开头的相对 URL。

- **谁拿得到**：`viewUrl` 只在上传者自己也满足这一行的下载角色时才返回，否则是 `null`。能上传不等于能下载；而且同名覆盖的行上，链接有效期内读到的可能已经是别人后来覆盖进去的内容。后端直接调 `BuildUrl` 不做这个判断，发给谁由业务决定。
- **有效期**：必须带，不签发永久链接。默认取 `LinkTtlMinutes`（60 分钟），签发时可以另传。
- **改不了**：签名编进了编码、相对路径和过期时刻，改其中任何一个都验不过。参数不全、签名不对、已过期，一律 `403`，也探测不出文件存不存在。
- **怎么显示**：`.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`、`.bmp`、`.pdf` 内联显示，其余一律按附件下载，包括 `.svg` 和 HTML。按后缀判断，不信上传时客户端报的类型。
- **怎么撤销**：没有单条撤销。等它过期；或者轮换 `Jwt:SecretKey`，签名随之全部失效，登录令牌也一起失效。

业务表里存相对路径，不存链接。

## 部署

### Windows：两种认证方式

**填账号密码。** 在文件服务器里填账号和密码，Windows 上内核用这个账号连接共享。根路径写成 `\\nas01\files` 这样的共享路径，密码加密存库。同一台主机只能用一套账号，见上面的[登记文件服务器](#登记文件服务器)。

**账号留空，用后端的运行身份。** 让后端以专用账号运行（IIS 应用程序池标识，或者 Windows 服务的登录身份），文件服务器的账号和密码都不填。服务器和 NAS 在同一个域时用域账号，根路径写主机名而不是 IP，这样能走 Kerberos。这种方式库里不存密码。

文件服务器一侧的建议：访问账号不放进管理员组，只给它需要的共享读写权限；SMB 最小协议设为 SMB2，关闭 SMB1。

### Linux 与 Docker：宿主机挂载

Linux 上内核不连接文件服务器，由宿主机用 CIFS 挂载共享，账号写在挂载凭据里：

```ini
# /etc/smb-nas01.cred，权限 600
username=svc-smartadmin
password=...
```

```text
# /etc/fstab
//nas01/files  /mnt/nas01/files  cifs  credentials=/etc/smb-nas01.cred,vers=3.1.1,uid=1654,gid=1654,_netdev  0  0
```

`vers=3.1.1` 是 SMB 协议版本，NAS 不支持时写 `vers=3.0`。`uid`、`gid` 要和容器里运行后端的用户一致：官方 .NET 镜像里的 `app` 用户是 1654，换了镜像先用 `docker exec <容器> id` 确认。

再把挂载点映射进容器，白名单填挂载根目录：

```yaml
services:
  app:
    volumes:
      - /mnt/nas01/files:/mnt/nas01/files
    environment:
      SmartAdmin__FilePath__AllowedRoots__0: /mnt/nas01
```

配置页里，文件服务器的根路径填容器里看到的 `/mnt/nas01/files`，账号和密码留空。Linux 上配置页把这两个输入框置灰，提示账号和密码由宿主机挂载时提供。已经填了账号的行（比如从 Windows 环境迁过来的数据）在 Linux 上忽略账号，第一次用到时记一条警告日志。

### 数据保护密钥

保存密码时，内核先查数据保护密钥是不是进程内临时密钥，是就拒绝（`44156`）：重启后临时密钥就丢了，存下去的密码永远解不开。开发环境内核会生成一把开发密钥并落盘，不受影响。生产要显式配 `SmartAdmin:Security:DataProtection:Key`。多副本还要共用同一份，配法见[容器化与多副本](/zh/guide/deployment/docker)。这把密钥和 TOTP、第三方登录、AI 厂商的 Key 用的是同一套。

只用「账号留空」的认证方式，库里没有密码，用不着它。

### 多副本

多副本部署下，同一个分片上传的各片可能落到不同副本，所以 `StagingPath` 要放在共享卷上，或者让负载均衡开会话保持。Linux 上每个副本都要挂载同一个共享，挂载点路径一致。

## 排错

### 文件夹无法访问

访问文件服务器失败时，界面会给出一个原因。测试连接和在线状态把它作为结果里的原因值返回，上传和下载则报 `44114`，原因放在参数里：

| 原因 | 怎么查 |
|---|---|
| 拒绝访问 | 账号对这个共享或文件夹没有权限 |
| 找不到网络路径 | 主机名解析不了，或者主机不可达 |
| 共享不存在 | 主机通了，但没有这个共享名 |
| 账号或密码错误 | 含密码已过期 |
| 账号被锁定或停用 | 去域控或 NAS 上解锁 |
| 凭据冲突 | Windows 错误 1219，见下面 |
| 超时 | 测试连接 5 秒内、在线状态 3 秒内没有结果 |
| 文件夹不存在 | 只读的文件路径，文件夹没建 |
| 文件服务器繁忙 | 这台服务器同时在做的文件操作超过 16 个，稍后再试 |
| 未知错误 | 没有归入以上几类，去后端日志里找完整的异常和系统错误码 |

白名单后来改小、根路径落到名单外时，上传和下载直接报 `44152`，不会走到上面这些原因。测试连接和在线状态不去碰这个路径，原因显示为「拒绝访问」。

账号或密码错误时，内核不会在每个请求里重试，免得几分钟就把域账号锁住。改正配置，或者点一次「测试连接」，才会再试。网络类的失败过 30 秒会再试。

出现找不到网络路径或超时这类网络类失败后，30 秒内这台服务器的上传、下载、删除直接报 `44114`，原因沿用那次失败的，不再去碰文件服务器。这样请求不会个个卡到系统的网络超时，把后端的线程占满，登录等其他接口照常响应。30 秒后放一个请求过去试探，成功就恢复，失败再挡 30 秒。测试连接和在线状态不受这个限制，成功时立即恢复。每台服务器同时在做的文件操作最多 16 个，超出的请求直接报「文件服务器繁忙」。这些状态只在各副本自己的内存里。

### 凭据冲突

Windows 的同一个登录会话对同一台主机只接受一套凭据，第二套会得到错误 1219（`ERROR_SESSION_CREDENTIAL_CONFLICT`），界面显示「凭据冲突」。后端日志里记作「Win32 错误 1219」，直接搜这个数字就能找到。有两个常见来源：

- 同一主机上配了不同账号。保存时已经保证同一主机的各行一致，除非是直接改库造成的。
- 后端进程所在的登录会话里，别的程序已经用另一套凭据连着同一台主机。本机用 `dotnet run` 开发时，后端跑在你自己的登录会话里，资源管理器正用你的账号打开着同一台 NAS，就是这种情况。开发环境的文件服务器账号留空，用你自己的身份访问即可。

后端遇到 1219 时，会断开自己连着这台主机的所有共享，再重连一次，仍然冲突才报错。部署时让后端用独立的运行身份，不和其他程序共用。

## 错误码

文件路径占 `44100`–`44199`，沿用[错误码](/zh/backend/error-codes)的分段。

| 码 | 含义 |
|---|---|
| `44101` | 编码不存在或已停用 |
| `44102` | 编码已存在 |
| `44103` | 编码格式不合法 |
| `44104` | 可写的行缺后缀白名单或大小上限 |
| `44105` | 后缀白名单格式不合法，须以点开头、最多 15 位字母或数字，逗号分隔 |
| `44106` | 只读的行不允许上传或删除 |
| `44107` | 没有上传权限 |
| `44108` | 没有下载权限 |
| `44109` | 后缀不在白名单内，含没有后缀的文件 |
| `44110` | 超过大小上限 |
| `44111` | 同名文件已存在 |
| `44112` | 路径不合法。下载、删除的 `path` 和配置的子文件夹：绝对路径、盘符、`:`、控制字符、空段、`.` 或 `..`、以点或空格结尾的段，或越出了文件夹，子文件夹里以点开头的段也算。业务指定路径的 `subPath` 先逐段清洗，只有绝对路径、空段、`.`、`..` 和清洗后超过 255 字节的段才报这个码 |
| `44113` | 文件不存在，含任何一段以点开头的路径 |
| `44114` | 文件夹无法访问，附原因 |
| `44115` | 分片缺失，补传后可以再次合并 |
| `44116` | 合并后的 SHA-256 与声明不一致 |
| `44117` | 上传会话无效：Id 格式不对、不存在或已过期，不属于当前用户或编码，或已被另一次合并认领。初始化时 `sha256` 不是 64 位十六进制或 `size` 为负数、分片序号越界、分片长度与应有长度不符，也报这个码 |
| `44150` | 文件服务器不存在或已停用 |
| `44151` | 文件服务器名称已存在 |
| `44152` | 根路径不在白名单内，保存时和每次上传下载都会校验 |
| `44153` | 填了账号，但根路径不是 `\\主机\共享` 形式 |
| `44154` | 同一台主机已配置另一个账号 |
| `44155` | 文件服务器仍被文件路径引用，不能删除 |
| `44156` | 数据保护密钥是进程内临时密钥，拒绝保存密码 |
| `44157` | 修改时换了主机或账号，密码却留空 |

`44154` 的补救：要给一台主机换账号，直接修改这台主机上任意一行的账号和密码，其余几行会一起改掉。新增的行或要换到这台主机的行，先填这台主机现有的账号，保存后再按需要统一换。
