# 文件路径：实施期间的决定与暂缓项

配套文档：规格 `docs/superpowers/specs/2026-10-20-file-path-design.md`，计划 `docs/superpowers/plans/2026-10-20-file-path.md`。

这份记录列的是实施时由执行方拍板、规格和计划没有写死的决定。每条写清楚做了什么、为什么，以及如果判断错了要付出什么代价，方便事后逐条复核。

## 一、安全与鉴权

| 决定 | 理由 | 如果错了 |
|---|---|---|
| 运行时角色串含解析不了的项，整行不可用（记警告、报 `44104` 规则不完整）；配置页照常显示，重存一次即恢复 | 鉴权边界要失败即关闭；坏值说明数据被改坏，整行停用最容易被发现 | 手工改坏的行连后端直调也失败，直到管理员重存 |
| 可写行缺后缀白名单或大小上限时，运行时同样报规则不完整 | 规格要求可写行两项必填，库被改坏时失败即关闭 | 无 |
| 只读行也拒绝删除 | 规格「只读：不开放上传，只提供下载」，删除是写操作 | 业务要在只读行删文件得先改配置 |
| 直链验签对规范化失败的路径返回 false，不抛异常；`exp` 无法解析时框架回 400 | 读文件之前一律 403/400，不泄露文件是否存在 | 无 |
| 直链内联的图片和 PDF 都加 `Content-Security-Policy: sandbox` | PDF 能带脚本，图片加了也不影响显示，分支更简单 | 只在 Edge 里验证过；某个浏览器的 PDF 查看器若在沙箱里显示异常，需要去掉 PDF 的 sandbox |
| 子文件夹拒绝 Windows 保留设备名（`CON`、`COM¹` 等），根路径拒绝控制字符 | 设备名在 Windows 上打不开，NUL 会让路径函数抛 500 | 无 |
| `StagingPath` 落在 `AllowedRoots` 之下时启动失败，检查在选项单例解析时执行 | 否则分片能按路径下载；相对路径要先按 ContentRoot 解析，注册时拿不到宿主环境 | 只有 `FilePathStagingSweeper` 启动时解析单例；若消费者移除它，违规配置会推迟到第一次上传才报错 |
| 上传服务的 `AdminFilePathOptions`、`ICurrentUser` 改为必需构造参数 | 可选的话，缺注册时分片会话会静默绑定到用户 0 | 消费者手工 new 这个服务时要多传两个参数 |

## 二、文件服务器账号与连接

| 决定 | 理由 | 如果错了 |
|---|---|---|
| 已存密码只在主机和账号（不区分大小写）都没变时沿用；改了主机或账号而密码留空，报 `44157` 要求重填（连接器不支持账号的平台除外） | 密码只对原主机原账号有效，空信封还会被级联到整台主机 | 改主机后忘填密码的管理员会被拦下，需要再填一次 |
| 同一主机多行时，改一行的账号或密码，其余行一起改（同一事务、失效解析缓存、记一条 Information 日志）；只改名称不级联；新增或换到另一台主机时账号不一致仍报 `44154` | 原实现让同主机多行完全改不了账号，只能删了重建；Windows 对一台主机只认一套凭据 | 用户若不希望一行的修改波及别的行，回退为 `44154` 拒绝即可 |
| 连接器按主机记凭据：换凭据前断开本进程连着这台主机的所有共享；遇到 1219 断开整台主机再重连一次 | 与 Windows 主机级凭据约束一致 | 同主机还有文件开着时断不开，新凭据要等下次访问才生效 |
| 凭据指纹用账号和明文密码的 SHA-256（只在内存里） | 密码信封带随机数，每次加密都不同，表达不了「凭据变了才重连」 | 无 |
| 填了账号但没有可用密码时，调用 `WNetAddConnection2W` 传空串而不是 NULL | NULL 表示该账号的默认密码，行为不确定 | 依赖默认密码的部署连不上（规格没有这种用法） |
| 等锁用调用方的取消令牌；持锁后的系统调用只受连接超时约束，结果一定记下 | 保证「错密码不重试」不会因为调用方先放弃而失效 | 在线状态的单行最长要等 15 秒才释放锁内调用（调用方自身仍按 3 秒返回） |
| 连接超时记为网络类失败，30 秒内不再试；断开返回 2250 视为已断开 | 主机不通是最常见故障，退避必须生效 | 主机恢复后最多 30 秒才重新可用 |

## 三、熔断与在途上限

| 决定 | 理由 | 如果错了 |
|---|---|---|
| 按服务器熔断 30 秒、在途上限 16（`protected virtual`），探针受上限约束、不受熔断拦截 | 规格要求 NAS 断开时登录和其他功能不受影响，同步阻塞会占满线程 | 熔断误开时，30 秒内这台服务器报「文件夹无法访问」 |
| 试探名额放在真正碰文件系统的那一步，不放在解析路径时 | 只写暂存的分片请求会占掉名额，只做上传的业务可能一直恢复不了 | 无 |
| 试探请求连上了只是业务失败（文件不存在、撞名、拒绝访问）也关闭熔断；取消不改变熔断 | 服务器是通的，不该再挡 30 秒 | 试探请求在碰服务器前就因校验失败（如非法子路径）时也会关闭熔断，之后一轮请求碰到宕机服务器再重新熔断 |
| Win32 错误码 51、59、64、1203、1222、1231、1232 归为找不到网络路径，121 归为超时 | 否则这些网络故障归为「未知」，熔断不会打开 | 无 |
| 在线状态每台服务器同时最多探 8 个，排队在超时之外 | 一页 20 行挂在同一台服务器上时，探测会自己挤满 16 个名额、误报繁忙 | 服务器慢于 3 秒时，超时的探测在底层 IO 返回前仍占着名额，第 3 批起仍可能报繁忙；一页很多行时状态列要等十几秒 |

## 四、上传、覆盖与分片

| 决定 | 理由 | 如果错了 |
|---|---|---|
| 覆盖时目标已存在用 `File.Replace`，否则 `File.Move`；并发替换的 1175/1176/1177 和目标中途消失按瞬时失败有界重试 | 规格要求有人在下载时覆盖也能成功，模板、安装包正是边下边换 | Windows 上覆盖正在下载的文件最终仍失败时，约 1.4 秒后才报错；SMB/NAS 上的语义本机无法验证 |
| `File.Replace` 的备份名以点开头，用完即删 | 备份名属于隐藏段，下载不可见 | 删除失败时留下隐藏的残留文件，没有清扫 |
| 三种命名规则落盘的后缀都转小写 | 规格要求后缀取清洗后的扩展名并转小写，落盘和校验用同一个值 | 业务自己拼大写后缀的路径去下载会找不到（应使用上传返回的 `path`） |
| `subPath` 里的非法字符按文件名规则清洗（`A:B` → `A_B`），结构性问题（绝对路径、盘符、`..`、控制字符）拒绝 | 两种都能防 NTFS 备用数据流，清洗后的路径通过返回值告诉业务 | 传 `a:b` 的业务拿到 `a_b`，而不是报错 |
| 子文件夹里以点开头的段在配置时拒绝；下载路径里的点开头段按「文件不存在」处理 | 下载路径的规范化和配置共用一个函数，下载时这类段应当看起来不存在，而不是报路径非法 | 无 |
| 分片会话用 `FileMode.CreateNew` 的标记文件认领合并 | 在 Windows 和 POSIX 上都是原子独占创建 | 进程在合并中崩溃时标记残留，会话由清扫器按 TTL 删除 |
| 缺片时保留会话以便补传；合并时文件夹不可访问或暂存读写失败也保留会话；合并成功或认领后核对没通过才结束 | 前端靠会话补传和重试合并 | 用户放弃的会话要等清扫器按 TTL 删除 |
| 续传只做同一次上传内：分片和合并按 1、2、4 秒重试三次，缺片补传一轮，任一片最终失败就取消其余在途分片；不做跨页面、跨重选文件的续传 | 规格「前端保留 uploadId，重传缺失的分片」的本意 | 关页面或重选文件要整个重传 |
| 前端重试时长（合计 7 秒）不随熔断（30 秒）延长 | 熔断期内快速失败本来就是目的 | 熔断期内用户多等 7 秒才看到报错 |
| 前端「换主机或账号要重填密码」的判断去掉「原来有密码」这个条件 | 与后端 `44157` 一致，否则前端会放行后端必拒的提交 | 无 |

## 五、测试与文档

| 决定 | 理由 | 如果错了 |
|---|---|---|
| 单文件阈值用例对 20 MB `File` 改为按身份比较 | 深比较单条要 1.6 秒，并行跑时超过默认 5 秒；身份比较更严 | 无 |
| `HostEndpointsTests` 判断上传模块路由缺席时，只匹配 `"/api/v1/sys/file/`，并断言文件路径的路由仍在 | 文件路径是独立的 `FilePath` 模块，禁用 `Upload` 不该让它消失 | 无 |
| 测试里的共享根写成 `//nas01/files` | Linux CI 上 `\\nas01\files` 不是绝对路径；Windows 连接器会把 `/` 规范成 `\` | 无 |
| `site/` 下的文档一段一个物理行 | 现有页面都是这样；VitePress 没有 CJK 软换行插件，中文段内换行会渲染出空格 | 只影响源文件可读性 |
| 「有效角色」的取法照抄仓库已有的五处写法，没有抽公共方法 | 抽出来会动 `MenuService`、`RbacPermissionProvider` 等无关代码 | 口径变化时要改五处 |

## 六、暂缓的已知问题

都不阻塞发布，影响都是多一轮超时或多报一次错，之后自己恢复。

- 清空账号后主机不通时，断开连接超时没有退避；熔断窗口过后的第一个请求要等满 15 秒。
- 编辑服务器时临时填另一台可达主机点「测试连接」，成功会关掉已保存服务器的熔断，下一批真实请求再卡一轮超时。
- 新增同主机的行只校验账号、不校验密码；两行密码不同时，连接器会在这两行之间来回断开重连。
- 熔断状态只在各副本自己的内存里。
- 合并在客户端超时后重试，如果服务端其实已经合并完，会报 `44117`（合并请求有 10 分钟超时，很少发生）。
- 前端把所有 `TypeError` 当成网络错误重试，代码缺陷也会重试三次才报出来。
- 组件卸载后，浏览器仍会把整个文件读完算完 SHA-256 才停下。
- 没有权限的用户能通过两个不同的错误码，探测出某个文件路径编码是否存在（编码不是机密）。
- 点开头的段在 NAS 开着 8.3 短名时可以按 `SECRET~1` 这类短名访问到，仍要满足下载角色；部署文档建议关闭 8.3 短名。

## 七、没有实测的部分

- 真实 SMB/NAS 上的账号连接、1219 冲突、覆盖替换语义。
- Linux 上的 CIFS 挂载。
- PDF 内联 sandbox 只在 Edge 里看过，Chrome、Firefox 没看。

本机验证用的是本地目录：MinimalHost + Vite + Edge，在浏览器里直接调用前端上传函数，传了 19 B 和 26,214,523 B 两个文件，两种命名规则，落盘和下载的 SHA-256 一致。
