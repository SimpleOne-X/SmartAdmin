# 文件路径实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在内核里新增「文件路径」。
管理员登记文件服务器，再按编码配置文件夹；
业务通过独立的上传、下载接口按编码读写文件。
这套功能与现有的 `sys_file` 上传完全不相干。

**Architecture:** 后端新增两张表 `sys_file_server`、`sys_file_path`。
服务放在 `SmartAdmin.Services/FilePath/` 下，包括：两个配置服务、解析器、连接器、上传服务、下载服务、角色判断。
签名直链的接口放在 Core，实现放在 AspNetCore。
HTTP 层是四个 `[Module("FilePath")]` 控制器：
两个配置控制器走菜单权限；上传、下载两个控制器走 `[ActiveSession]`，再按行配置的角色判断。
前端新增配置页（两个页签）、`FilePathUpload` 组件和接口封装。

**Tech Stack:** .NET 10、SqlSugar、xUnit v3（Microsoft.Testing.Platform）、Vue 3 + Naive UI + vitest。Windows 上用 P/Invoke 调 `mpr.dll`。

**Spec:** `docs/superpowers/specs/2026-10-20-file-path-design.md`

## Global Constraints

- 核心包只依赖 SqlSugarCore + Microsoft.\*。不引入 SMB 客户端库，Windows 连接用 `mpr.dll` 的 P/Invoke。
- 内置服务一律 `TryAdd*` 注册。
  长方法拆成 `protected virtual` 步骤。
  新接口写进 `backend/tests/SmartAdmin.Tests/ReplaceabilityContract.cs` 的 `Points`，生命周期和注册时一致。
- 权限码是规范化路由 `{METHOD}:/{路由模板}`。错误是数字 `ErrorCode` 加 `[MsgKey]`，文案只放前端语言包。

- 示例主机名、共享名一律用 `nas01`、`files`、`svc-files` 这类虚构值。仓库是公开的。
- 后端测试跑在 MTP 上：`dotnet test backend/SmartAdmin.slnx -- --filter-class "*X*"`（不是 `--filter`）。
  前端单文件测试：`cd web/packages/admin && npx vitest run <路径>`。

## 与规格的出入（计划里定下的）

- 菜单按钮标题用「更新」，不用「编辑」，与现有种子一致（`岗位-更新`、`AI 厂商-更新`）。
- 前端接口照现有写法放进 `web/packages/admin/src/api/index.ts`，不新建 `api/filePath.ts`。

  `translateError` 遇到字符串类型的 `args.reason` 时，先查 `error.reason.<值>` 换成文案。
  测试连接、在线状态返回的原因用同一套键。
- 规格第十三节留给实施者的事项，在这里定下：
  - 两张表继承 `BaseEntity`。
  - 错误码见 Task 1。
  - 分片暂存的清扫用托管服务。
  - 在线状态不缓存。
  - P/Invoke 用 `DllImport`。
  - 菜单图标用 `ph:hard-drives-duotone`。

## Review Focus

以下五类输入，规格隐含要求、但只靠功能测试抓不到。按出事概率从高到低排列：

1. **伪造的 `uploadId`。**
   `uploadId` 会被拼进暂存路径。
   如果传进来的是 `..\..\x`，或者是别人的 Id，都应得到「上传会话无效」，并且不能读写暂存目录以外的任何东西。
   由 Task 6 的测试覆盖。
2. **Windows 会吞掉路径段末尾的点和空格。**
   `a.pdf.` 实际打开的是 `a.pdf`，`.. ` 的效果接近 `..`。
   所以相对路径里任何一段以点或空格结尾都要拒绝。由 Task 1 的测试覆盖。
3. **截断文件名时切开代理对。**
   名字里有 emoji，截到 60 个字符时可能正好切在代理对中间。截断后不能出现孤立的代理字符。
   由 Task 1 的测试覆盖。
4. **下载流还开着时覆盖同名文件。**
   读文件时没带 `FileShare.Delete`，Windows 上 `File.Move(overwrite: true)` 会失败。
   正在下载时覆盖上传应当成功。由 Task 7 的测试覆盖。
5. **后缀的大小写，以及没有后缀的文件。**
   白名单是 `.pdf` 时，`报价.PDF` 应当通过，落盘的后缀是小写；`README` 这种没有后缀的文件应当拒绝。
   由 Task 5 的测试覆盖。

`SmartAdminOptionsSetup`：
- 照 `Upload` 的工厂写法，用 `TryAddSingleton` 注册 `options.FilePath`，把 `StagingPath` 按 ContentRoot 解析成绝对路径。
- 在注册之前同步校验配置，不合法就抛 `InvalidOperationException`，写法同 `MaxPageSize`：
  - `AllowedRoots` 的每一项都必须满足 `Path.IsPathFullyQualified`。
  - `LinkTtlMinutes` 和 `StagingTtlHours` 都必须大于 0。

`NormalizeRelative` 依次处理：
1. 把 `\` 换成 `/`。
2. 以下情况一律拒绝：以 `/` 开头、含 `:`、含控制字符（`< 0x20` 或 `0x7F`）、`Path.IsPathRooted` 为真、有空段、有 `.` 或 `..` 段、有以点或空格结尾的段。

`SanitizeFileName` 依次处理：
1. 取最后一段（把 `\` 当作分隔符）。
2. 非法字符和控制字符换成 `_`。
3. 去掉末尾的点和空格。
4. 开头是点的，把这个点换成 `_`。
5. 按最后一个点拆出主干和后缀，主干截到 60 个字符；如果第 60 个字符是高代理，就只留 59 个。
6. 第一个点之前的部分如果是保留设备名（不区分大小写），前面加 `_`。
7. 结果为空时用 `file`。

`IsUnder` 是安全边界，按下面的写法实现：

```csharp
public static bool IsUnder(string path, string root)
{
    var cmp = OperatingSystem.IsWindows() ? StringComparison.OrdinalIgnoreCase : StringComparison.Ordinal;
    var full = Path.TrimEndingDirectorySeparator(Path.GetFullPath(path));
    var baseDir = Path.TrimEndingDirectorySeparator(Path.GetFullPath(root));
    if (full.Equals(baseDir, cmp)) return true;
    var prefix = Path.EndsInDirectorySeparator(baseDir) ? baseDir : baseDir + Path.DirectorySeparatorChar;
    return full.StartsWith(prefix, cmp);
}
```

`FromException` 的判断顺序：
1. `FileServerConnectException` → 它的 `Reason`。
2. `TimeoutException` → timeout。

连接器的状态机按下面的算法写。每个共享一把 `SemaphoreSlim`，状态存在 `ConcurrentDictionary<string share, ShareState>` 里：

```text
EnsureConnectedAsync(target, retryFailed):
  UserName 为空 → 返回
  share = TryGetShare(RootPath)            // 解析失败 → 抛 FileServerConnectException(unknown)
  fp = SHA256(share \n UserName \n PasswordProtected)
  进锁(share):
    state.ConnectedFp == fp → 返回
    state.FailedFp == fp 且 !retryFailed:
       凭据类失败 → 直接抛记下的原因
       网络类失败且距上次失败不足 30 秒 → 直接抛记下的原因
    state.ConnectedFp 不为空:
       rc = CancelConnection(share)；rc == 2401 → 记一条信息日志，返回（继续用旧连接）
    rc = 在线程池执行 AddConnection(share, UserName, Unprotect(PasswordProtected))，套 WaitAsync(ConnectTimeout)
    rc == 1219 → CancelConnection(share)，再 AddConnection 一次
    rc 为 0 或 85 → ConnectedFp = fp，清掉失败记录
    否则 → 记下 FailedFp、失败类型和时间，抛 FileServerConnectException(FromWin32(rc), rc)
  超时 → 抛 FileServerConnectException(timeout, 0)
```
